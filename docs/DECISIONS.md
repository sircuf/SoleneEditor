# 결정 기록

바뀌면 지우지 말고 아래에 새 항목을 추가해요.

| 결정 | 이유 |
|---|---|
| APK가 아니라 GitHub Pages 웹 | 설치가 필요 없고, PC·iOS까지 지원하고, 업데이트가 즉시 반영돼요 |
| PWA 쓰지 않음 | 오프라인이 필요 없고, 업데이트 흐름이 단순해져요. 나중에 `vite-plugin-pwa`로 추가 가능 |
| Svelte 5 | 가볍고, RisuAI 본체가 Svelte + TS라 포팅이 쉬워요 |
| CodeMirror 6 | 모바일·한글 입력이 안정적이고 가벼워요 (Monaco는 모바일 미지원) |
| fflate | JSZip보다 빠르고 작아요 |
| 단일 문서 작업 공간 | MVP 단순화. 새 파일을 가져오면 기존 작업과 스냅샷을 삭제해요 |
| 스냅샷 보존은 용량 기준 | 한도를 넘으면 오래된 것부터 삭제. 원본·수동·내보낸 버전은 고정이라 제외 |
| 에셋은 보관만 | 편집 대상은 텍스트뿐. 스냅샷에는 에셋을 넣지 않아요 |
| 폼 ⇄ JSON 전환 | 데이터 원본은 하나. JSON 문법 오류 시 전환 차단. JSON 범위는 항목 단위 |
| PC 우선 | 모바일은 MVP에서 깨지지 않을 정도만 |
| ~~GPL-3.0~~ → AGPL-3.0 | RisuAI(GPL-3.0) 코드를 포팅하고, risum에 필요한 rpack이 RisuAI 밖에서는 AGPL-3.0이라서. 서버 없는 정적 사이트라 AGPL 추가 의무는 사실상 충족 |
| charx 내보내기 시 `character_book`을 module 로어북에서 다시 생성 | RisuAI 내보내기와 결과를 같게 하고, 다른 앱에서도 편집된 로어북이 보이게 하기 위해. 변환은 `exportCharacterCard`의 로어북 변환을 포팅 |
| IndexedDB 래퍼는 `idb` | workspace·스냅샷·보존 payload·draft를 여러 object store에 걸친 한 트랜잭션으로 교체해야 해요. 간단한 키·값 접근 위주인 idb-keyval보다 이 원자적 교체를 직접 표현하기 좋아요 |
| Phase 0 TypeScript는 최신 호환 안정판 6 사용 | npm 최신 TypeScript 7은 현재 svelte-check 4.7.6의 peer 범위(`^5.0.0 \|\| ^6.0.0`) 밖이에요. 검사 도구와 호환되는 6의 최신 안정판을 사용하고, 7 지원이 추가되면 함께 올려요 |
| 가져오기는 관대하게, 내보내기는 엄격하게 | 실제 파일에는 타입이 조금씩 어긋난 값이 많아요. 편집할 수 없을 만큼 구조가 깨진 경우만 거부하고, 나머지는 경고로 알린 뒤 오류가 있으면 내보내기에서 막아요 |
| 폼 입력은 300ms 디바운스, 한글 조합 중에는 반영하지 않음 | 키 입력마다 문서 전체를 갱신하면 느리고, 조합 중에 값을 덮어쓰면 한글 입력이 깨져요 |
| 스토어 갱신은 구조 공유(structural sharing) | 로어북 2,000개 기준으로 편집 한 번에 29ms이던 것이 약 2ms로 줄었어요 |
| charx 내보내기는 텍스트 항목만 deflate(level 6) | 이미 압축된 이미지·음성은 그대로 저장해 CPU를 아끼고, JSON은 압축해 파일 크기를 원본 수준으로 맞춰요 |
| 목록형 값은 선택 목록 (로어북 mode, 정규식 type, 트리거 type) | RisuAI UI의 선택지를 따라요. 목록에 없는 값도 보존해요 |
| 호환성 기준은 실제 RisuAI 출력 | 합성 샘플만으로는 우리 이해가 맞는지 검증할 수 없어요. RisuAI 자체 내보내기 코드로 만든 파일을 `tests/fixtures/real/`에 두고, 역방향(RisuAI가 우리 출력을 읽는지)도 확인해요 |
| 완성 전에는 배포하지 않음 (2026-09-30) | 사용자 결정이에요. Pages를 내리고 배포 워크플로우를 꺼 뒀어요. localhost에서만 테스트해요 |
| 커밋 이메일은 GitHub noreply 주소 | 공개 저장소라 개인 이메일이 커밋 기록에 노출되지 않게 해요. 공개 전에 기존 커밋도 모두 다시 썼어요 |
